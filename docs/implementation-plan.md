# 可扩展调度实施计划

目标：保留同步解析契约，增加可持久化的全局调度和异步任务，使 API 与 GPU 解析进程可以独立扩容。

已落地的流程与异常策略见[调度器实现与异常处理](scheduling.md)，操作步骤见[运维与扩容](scaling.md)。下列清单是实施记录，不替代当前实现说明。

- [x] 入口在 multipart 解析前实施请求体、上传并发和上传超时限制。
- [x] 上传、校验、存储、等待、SDK 和渲染阶段指标；只使用固定标签，不记录文档内容、文件名或部署地址。
- [x] SQLite WAL 事务队列：全局任务/工作量预算、去重、幂等键、租约、重试和过期清理。
- [x] 独立 worker：领取任务、定期续租、隔离执行结果、优雅停止。
- [x] 新增异步任务提交、查询和结果接口；同步接口通过同一调度层等待结果。
- [x] 文件存储抽象：调度端本地目录和 S3 兼容对象存储；任务行只保存对象键，worker 通过 HTTP 传输文件。
- [x] 自动化验证：并发领取、全局容量、失效租约、旧 worker 写入隔离、重复提交、错误恢复及 API 回归。
- [x] 容器部署、定速到达压测与真实 GPU 扩容验证。
- [x] 文档、暂存内容和提交元数据隐私检查。

选择 SQLite WAL 同时保存任务与队列，以短事务领取任务，模型执行期间不持有数据库锁。worker 通过认证的 HTTP 调度 API 领取、续租和提交结果，不直接打开数据库文件。初期保持每份 PDF 的完整 SDK 调用，不拆开跨页结构处理。SQLite 文件使用调度端的本地持久磁盘；解析 worker 可以跨机器扩容，调度端暂不提供跨节点主动主动复制。
